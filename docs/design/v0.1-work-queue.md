# V0.1 remaining-work queue

Status: **living document - edit in place, not append-only** (like
`SESSION_HANDOFF.md`, unlike the append-only `docs/changelog/`).
Source of truth for "what's left under V0.1, in what order." Every
item traces back to `docs/SESSION_HANDOFF.md`'s 2026-09-26 audit.

## How to use this

1. Take the first `[ ]` item whose **Blocked on** column is empty.
2. Work it: TDD as usual, decision record if it's a real design
   decision, changelog entry, commit implementation then docs
   separately (this project's standing convention).
3. Mark it `[x]`, add the commit hash(es) and decision-record number in
   the **Closed by** column, and update `SESSION_HANDOFF.md`'s audit
   section to match (that doc is the narrative; this one is the queue).
4. If working an item reveals a new one, add it to the bottom with the
   same columns, don't silently fold it into an existing row.
5. An item with something in **Blocked on** is not next - skip to the
   next unblocked `[ ]` row instead of stalling the whole queue on it.

## Explicitly not in this queue

- Provider "configuration forms" - deliberately not built, by design,
  not an oversight. Not queued because building it would be wrong, not
  because it's low priority.
- Cross-hypervisor provisioning abstraction (cloud-init/Ansible) -
  scoped and recommended against for now (`cross-hypervisor-
  provisioning-scoping.md`). Revisit only if that recommendation's own
  triggers (a real substrate change, or a fleet of guests needing
  convergence) actually occur.
- Phone-tether file/script exchange channel - this is V0.2 scope, not
  V0.1 remaining work; tracked in `SESSION_HANDOFF.md`, not here.
