# DR129 — Installed application inspection in managed Ubuntu VMs

2026-10-02. Accepted. First stage of requested existing-app recipe extraction.

## Implemented

Environment recipes page now accepts a managed VM name and installed Debian
package name. It submits inspect_app through the existing durable VM job runner,
shows results and directs disconnected users to Workload jobs. Native guest
queries use ProxmoxVmHost.guest_exec's existing VM/storage/attachment checks.
No new credential, app account, profile mount or data mutation is introduced.

The read-only dpkg-query adapter extracts installed package identity, version,
architecture, declared dependencies and /etc conffile locations. It does not read
configuration contents, profiles, package-maintainer scripts or personal data,
execute the application, fetch sources or resolve transitive installed locks.
Package options/patterns/shell text are refused before execution. Missing/non-
installed packages and malformed/unbounded metadata refuse. Output is a persisted
baseline.app-inspection/v1 report, not a deployable recipe. Fields explicitly mark
recipe_ready=false, sources_verified=false, test_install_verified=false and
state_coverage=unknown, with remaining steps. Conffile reference hashes are not
exported as source hashes or current configuration evidence.

Only managed running Ubuntu/Proxmox VM inspection is supported in this increment.
Container, Snap, OCI, Flatpak and other app adapters remain open. A Debian package
may be a wrapper/transitional package; inspection does not imply that its real
application medium is deb. App-specific export must resolve that before promotion.
