## Explicitly out of scope for this audit

`baseline/lib/` modules with no dedicated test file exist
(`acp_transport.py`, `firstboot_network_repair.py`, `handoff.py`,
`hardware.py`, `harness_adapter.py`, `netpref.py`, `network.py`,
`providers.py`, `repair_additive.py`, `repair_rollback.py`,
`tether.py`) - every one of these predates decision record 62 and
belongs to earlier, already-closed milestones (Track A1-A5, harness
adapters, etc.), not the persona/recovery/settings/backup arc this
item's own text scoped the audit to. Flagged here for visibility, not
silently ignored, but not fixed under this item - closing them would
be scope creep against the direct instruction's own stated boundary
("everything from decision records 62-75," not "everything in the
repo").

Also out of scope, per the instruction's own wording: adding a
numeric coverage-percentage tool. This project's established
convention throughout - a real Runner/FakeRunner-injected test file
per module, TDD-disciplined from the start - is the "TDD setup" the
instruction asked to confirm, not a specific coverage percentage;
no such tool exists anywhere in this repo's history, and introducing
one now would be new tooling investment beyond what was asked.
