# containers - block 001 (open)

Host-level containerized-service management (Podman, Quadlet, and any
sibling runtime/lifecycle code). Distinct from `proxmox` (Proxmox
guest VM/LXC orchestration) and from `docker_provision.py`'s job
(portable cross-hypervisor container images) - this category is for
code that manages a container *as a Baseline-run host service*. Rotate
to 002.md once this file exceeds ~400 lines or ~15 entries - see
INDEX.md.

## 2026-09-27 ~xx:xx - quadlet.py: Podman + Quadlet as the service-management layer (Track B4)

**Requested via:** chat ("Install and implement these: Podman +
  Quadlet for service management...")
**Context:** No existing Baseline module managed a containerized app as
  a host-level systemd service; `docker_provision.py` wraps the
  `docker` CLI for portable images but has no service-lifecycle
  concept. Fedora Hummingbird (Red Hat's 2026 agentic-OS prototype)
  independently converged on the same Podman+Quadlet combination for
  the same class of problem, cited as external validation during the
  research that led to this request.
**Considered:** Hand-written systemd unit calling `podman run` directly
  (rejected - needs its own bespoke stop/cleanup semantics; a
  `podman run` without `--rm` leaves a stopped container behind on
  every restart) vs. Quadlet `.container` files, which
  `systemd-quadlet-generator` turns into ordinary systemd units at
  `daemon-reload` time so every existing Baseline convention
  (`systemctl`/`journalctl`) keeps working unchanged (chosen).
**Requirement determined:** `generate_unit()` is pure (no I/O);
  `write_and_enable()` refuses outright if Podman isn't installed
  rather than guessing; `stop_and_remove()` never touches the
  container's image or any named volume, matching
  `repair_rollback.py`'s "never destroy data the operator didn't
  explicitly ask to lose" posture.
**Files changed:**
  - `baseline/lib/quadlet.py` - new.
  - `tests/unit/test_quadlet.py` - new.
  - `boot/provision.sh` - installs `podman`, creates
    `/etc/containers/systemd`, deploys `quadlet.py`, verification block
    checks both.
**Verification:** RED confirmed (`ModuleNotFoundError`) before
  implementation. 13 new tests, all passing. Full suite: 893/893 (868
  before this pair of changes) - see the `proxmox` category's matching
  entry for the vm_scripts.py half's 12 tests.
  **Not verified against real Podman, real systemd, or a real host.**
**Pointer update:** new `containers` row added to INDEX.md.
**Docs update:** decision record 58 added.

## 2026-09-27 ~xx:xx - quadlet.py rootless mode implemented for real; default corrected

**Requested via:** chat ("please workon the 4 you listed" - item #16)
**Context:** Record 58 shipped `ContainerSpec.rootless=True` as a field
  with no real behavior behind it - always wrote to the root-level
  `/etc/containers/systemd` regardless.
**Considered:** Keeping `rootless=True` as the default while
  implementing it for real (rejected once implemented - rootless mode
  needs a real, resolvable target user with no sensible universal
  default, so a `True` default would make the bare `ContainerSpec()`
  silently require an unstated prerequisite) vs. correcting the default
  to `False` to match Baseline's actual current reality (runs as root
  today) while still fully implementing rootless as a deliberate,
  explicit opt-in (chosen).
**Requirement determined:** Rootless mode must use a real per-user
  Quadlet path (resolved via `getent passwd`, never guessed as
  `/home/<user>`) and a real `systemctl --user` invocation with
  `XDG_RUNTIME_DIR` explicitly set (required - `--user` alone can't
  find the session bus from a root-invoked shell). Refuses cleanly,
  never guesses, when `.user` is unset or doesn't resolve.
**Files changed:**
  - `baseline/lib/quadlet.py` - `ContainerSpec.user` added, default
    `rootless` changed `True` -> `False`; `unit_path`/`_systemctl_prefix`/
    `_lookup_user_uid_and_home` added; `write_and_start`/
    `stop_and_remove`/`status`/`is_running` all gained rootless support.
  - `tests/unit/test_quadlet.py` - 8 new tests.
**Verification:** RED confirmed first. 8 new tests, all passing -
  existing 13 tests unaffected by the default change (they never set
  `rootless` explicitly, and the corrected default now produces exactly
  the root-mode behavior they already expected). Full suite: 922/922
  (902 before this entry - see the `proxmox` category for
  vm_scripts/vm_provision's 12 tests, 8 here).
**Pointer update:** containers row's entry count/date/summary updated
  below.
**Docs update:** decision record 61 added (shared with `proxmox`).
