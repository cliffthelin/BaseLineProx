## 2026-09-20 ~13:xx - Chat-tab quality assessment (decision only, no code yet)

**Requested via:** chat ("What gaps are there that would prevent me
  from having full quality Claude Code conversation / development from
  the Chat tab", then "Yes, then let's return to Claude if you feel we
  are ready...")
**Context:** `harness.ask()` calls `claude -p <prompt> --tools ""` -
  a single stateless call per message, zero tools, only the
  hardware/network JSON blob as context. User wants a real conversation
  with visible/toggleable access scope, and asked me to research
  before implementing.
**Considered:**
  1. Embedding the actual interactive `claude` CLI in a raw PTY inside
     a Textual widget (what the user's original phrasing implied - a
     literal "tab out of Claude Code back to Baseline" command). Real
     effort: a terminal-emulator-inside-a-terminal-emulator, plus
     needing to explicitly carve out Baseline's own bindings from
     whatever has PTY focus. No such widget is currently available in
     this project; not attempted.
  2. Keeping Baseline as the sole terminal/renderer, but making
     `harness.ask()` stateful and richer via CLI flags confirmed
     present in the installed `claude --help`: `--session-id
     <uuid>`/`-c/--continue` for real multi-turn memory, `-p
     --output-format stream-json` for real incremental streaming,
     `--allowedTools`/`--disallowedTools` for a real, named, auditable
     access-scope control (not all-or-nothing).
  Chose (2): it delivers everything asked for functionally (memory,
  streaming, visible scope) without the PTY-embedding risk, and
  because nothing ever captures raw keyboard focus away from Baseline,
  the "escape hatch back to Baseline" problem the user was solving for
  doesn't exist in this design - Tab/q/r keep working everywhere,
  always.
**Requirement determined:** Not yet finalized as a concrete acceptance
  test - this was a scoping/architecture conversation. Proposed shape:
  session-id-per-chat-session + `-p --output-format stream-json` +
  `--allowedTools` exposed as a header toggle showing the live-granted
  scope, plus a condensed one-line header (title | tabs | scope |
  memory | copy | datetime).
