## 2026-09-29 ~13:45 - real, safe "live install screen" viewer

**Requested via:** chat, direct instruction ("keep things improving")
  following a real mistake: a manual `nc`-piped `screendump ...\nquit\n`
  accidentally terminated a real, in-progress install (`quit` is a
  genuine QEMU monitor command, not just a way to close the shell
  pipe).
**Context:** Checking a real install's progress required hand-typing
  raw QEMU monitor commands over a socket - exactly the kind of
  manual, error-prone, easy-to-get-wrong action this project's whole
  session had been moving away from.
**Considered:** Shelling out to ImageMagick/ffmpeg to convert the raw
  PPM screendump to a browser-displayable format vs. a minimal
  stdlib-only PNG encoder - the latter chosen: neither tool is
  provisioned anywhere in this project, and a ~40-line PNG encoder
  needs no new dependency at all.
**Requirement determined:** A real, permanent, safe "view the current
  install screen" feature - never sends anything but the one real
  `screendump` command, manual Refresh only (never auto-polling, so it
  can't hammer a real QEMU process), genuine error (never a fake
  image) when no install is running.
**Files changed:** see decision record 108 for the full list -
  `drive_setup_install.py` (3 new functions), `baseline_web.py` (new
  route, UI section, `_binary_response` helper).
**Verification:** Full suite 1539/1539 (was 1533). Real Unix socket
  test servers stand in for QEMU's own monitor in both new test files,
  directly proving `quit` is never sent. Not yet live-verified against
  a real, actively-running install - next real `build_self_installer`
  attempt is the actual proof.
**Pointer update:** ui row's entry count/date/summary updated below.
**Docs update:** decision record 108 added.
