## 2026-09-29 ~17:20 - the install invocation's own base boot order never fell back to disk, so the auto-installer's own reboot re-entered itself

**Requested via:** chat, real live bug found immediately after decision
  record 115's fix let a real install reach genuine completion (99%,
  "make system bootable") for the first time - the deepest real
  progress in this entire debugging chain
**Context:** A raw byte read of `/dev/sdd`'s first sector (bypassing
  the host kernel's stale partition-table cache) confirmed a real,
  fresh GRUB boot-sector signature being written at 99%. A follow-up
  screendump one minute later, expecting completion, instead showed
  the installer back at "Preparing installer mount points..." - it had
  rebooted (Proxmox's own automated installer does this after a
  successful install) but re-booted the *CD-ROM* again, not the disk,
  because `-boot order=d,once=d` used `d` as both the one-time
  override *and* the base order - `once=` only affects the very first
  boot of the process's life, so every later boot (including this
  self-triggered reboot, which happens inside the same still-running
  QEMU process) fell back to `d` forever. This exact failure mode was
  already described in the function's own docstring citing decision
  record 04, but the fix had never actually been applied to this
  invocation.
**Considered:** N/A - once diagnosed, the fix is using `c` (disk) as
  the base order so only the true first boot uses the CD-ROM.
**Requirement determined:** The base boot order must be `c`, with
  `once=d` overriding only the process's first boot.
**Files changed:** `drive_setup_install.py`
  (`build_sparse_install_invocation`'s `-boot` argument corrected in
  both branches), `test_drive_setup_install.py` (existing boot-order
  test corrected and renamed; SCSI-branch test gained the same
  assertion).
**Verification:** Full suite 1552/1552. Found via a real install
  reaching genuine completion for the first time and then directly
  observed, via a real screendump, looping back into the installer
  instead of booting the installed system. A real, self-triggered
  retry with this fix applied was launched after writing this record;
  full end-to-end confirmation is still pending.
**Pointer update:** proxmox row's entry count/date/summary updated
