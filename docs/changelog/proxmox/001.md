## 2026-09-26 ~xx:xx - vm_provision.py: Track A4's manual qm workflow generalized into reusable code

**Requested via:** chat (cross-session design review flagged "no code
  path that creates, starts, stops, or configures a VM/container -
  grepping the tree found nothing" despite Track A4 having proven the
  full workflow manually; asked to vendor/port Proxmox VM tooling,
  specifically full VMs rather than LXC, given the project's own "spin
  up any OS" goal)
**Context:** Track A4 (this plan's real-hardware track) created VMs,
  attached persistence-backed disks, and safely retired a VM without
  losing its persistence disk - all by running the equivalent commands
  by hand and observing the real result, never committed as reusable
  code. LXC (`pct`) was considered and rejected as the wrong primitive
  for "any OS" specifically because it shares the host kernel and can
  only run Linux.
**Considered:** Vendoring community-scripts/ProxmoxVE's own scripts
  unmodified (rejected for this pass - most of that repo is LXC
  app-installers, the wrong category here, and executing someone
  else's live script contradicts this project's "nothing here trusts
  that proposal" boundary) versus writing a Baseline-native module
  following this project's own established Runner/argv-builder
  convention (chosen - matches `proxmox_vm_metrics.py`'s existing
  read-only half of the same pattern).
**Requirement determined:** Every operation Track A4 proved by hand
  gets a pure, testable argv-building function plus a thin
  Runner-executed wrapper; the destroy-preserving-persistence sequence
  must reassign the disk to a fresh VMID before destroying the
  original, and must never destroy the original at all if that
  reassignment fails - proven directly against a fake runner, not
  assumed from reading the code.
**Files changed:**
  - `baseline/lib/vm_provision.py` - new; `next_free_vmid`,
    `create_vm`, `attach_persistence_disk`, `start_vm`, `stop_vm`,
    `retire_vm_preserving_persistence`, plus each one's `*_argv`
    builder.
  - `tests/unit/test_vm_provision.py` - new, 15 tests (RED confirmed
    first: `ModuleNotFoundError: No module named 'vm_provision'`).
  - `docs/design/decision-records/34-vm-provision-module.md` - new.
**Verification:** RED confirmed before implementation; 15/15 new tests
  passing; full suite 644/644 (629 before this change), no
  regressions; `vm_provision.py` byte-compiles clean. Not yet
  verified: a real `qm`/`pvesh` round trip on real Proxmox hardware -
  the argv shapes match Track A4's own real, working commands, but
  this committed code has only run against a fake runner so far.
**Pointer update:** new `proxmox` category row added to INDEX.md.
**Docs update:** decision record 34 added under
  `docs/design/decision-records/`.
